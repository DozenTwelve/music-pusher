What it changes, and what it leaves alone

It reads the album, works out how many albums Navidrome would make of it and why, and offers one fix for each cause. Every fix is a switch, and nothing is written until you press the button.

  • The tags Navidrome groups by: album name, album artist, release date, album version and MusicBrainz album ID, made the same on every track.
  • The date, when the tracks disagree on it, so the album shows a year.
  • Track numbers, written as 3/12 and counted per disc.
  • Damaged text (Don_t, stray control characters, trailing spaces) where the repair is certain, and file names that lost an apostrophe.
  • The cover: put into every track that lacks it, and saved as cover.jpg beside them, which is the first place Navidrome looks.

The audio is never re-encoded. Only the tags are rewritten. The test suite compares the md5 of the decoded audio before and after on every file it fixes, and they match.

Everything else goes into the zip as it was: the other tags (genre, comments and the rest), scans, logs, cue sheets, and any file it cannot read. The Finder’s .DS_Store and __MACOSX folders are left out. When it has finished, it opens the zip it made and reads every track again, so the count it shows you is of the files you download.

What it can’t fix

These it points out and leaves to you:

  • Missing tracks. A gap in the numbering stays a gap.
  • Several tracks with the same number, which is usually a multi-disc set with no disc numbers in the tags. It can’t know which track is on which disc.
  • A track with no number, when its file name has none either.
  • FLAC and MP3 mixed in one album, or tracks of different quality. Converting would mean re-encoding.
  • A FLAC file that doesn’t record its length. That also needs re-encoding.
  • Tracks with no title or no artist. It won’t guess them.
  • Damaged or cut-short files, and audio in formats other than FLAC, MP3 and M4A. They go into the zip untouched.

It looks nothing up online, so it can’t tell you the right release date or fetch a cover. If an album has no cover, you can drop in an image of your own.

Limits

Browser
Firefox or Chrome on a computer. On a phone or tablet the page explains itself but the tool doesn’t open.
Formats
FLAC, MP3 and M4A.
Size
2 GB an album, 300 MB a track. One album at a time.
Zip files
Up to 4 GB, without a password. File names in an old encoding (GBK, Shift_JIS) are read by a guess, and the page warns you when it guessed.

Questions

Is anything uploaded?

No. The page is a set of static files. The album is read and rewritten inside the browser tab by TagLib, compiled to WebAssembly, and the zip is put together in the tab and saved like any download. The page’s own code loads nothing from anywhere else; Cloudflare, which hosts the site, adds its own visit counter to every page. The album you drop in is never sent anywhere.

Does it work for Plex, Jellyfin or other players?

The rules it follows are Navidrome’s, checked against a real Navidrome 0.63.2. The tags it writes are ordinary tags that any player reads, but other players group albums in their own way, and none of them was tested. It may help; we can’t promise it.

I changed PID.Album in my Navidrome config.

Then Navidrome groups albums by your rule, not the default one this page checks against. The tag fixes are still sound, but the album count the page shows may not be what you get.

Why does it want a zip back instead of fixing my files?

A web page can’t write into your folders. You replace the old folder with the one in the zip and rescan in Navidrome. Your originals stay as they were until you do.

Where is the code?

On GitHub, under the MIT licence. The same repository has a self-hosted version that runs on your server next to beets and Navidrome.
